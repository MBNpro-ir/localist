# راهنمای Developer Bridge

## دو مسیر

صفحه Developer Bridge در نسخه ویندوز دو گزینه دارد: **هات‌اسپات گوشی** و **اینترنت / RustDesk**. روشن‌کردن کلید ADB ویندوز فقط ابزار ADB و فهرست دستگاه‌های واقعاً متصل را آماده می‌کند.

### هات‌اسپات گوشی

1. رایانه را به هات‌اسپات گوشی وصل کنید.
2. نشانی دقیق endpoint فعال ADB گوشی را به شکل IP:port وارد و «اتصال ADB» را انتخاب کنید.
3. در صورت اتصال مجاز، دستگاه باید در کارت وضعیت و Android Studio (با همان Android SDK Platform-Tools) دیده شود.

**هات‌اسپات به‌تنهایی ADB را روشن نمی‌کند.** در Android عادی، ADB بدون کابل به Wireless debugging فعال نیاز دارد؛ روش قدیمی adb tcpip هم اتصال اولیهٔ USB لازم دارد. اگر Wireless debugging روی گوشی در حالت hotspot قابل روشن‌کردن نیست و کابل هم استفاده نمی‌شود، endpointی وجود ندارد و اتصال ممکن نیست. Localist این محدودیت را دور نمی‌زند.

### اینترنت با RustDesk

1. Localist گوشی باید با اینترنت آنلاین باشد. شناسه و رمز نشست آن را در صفحه وارد و «باز کردن تونل شبکه RustDesk» را انتخاب کنید.
2. فقط اگر گوشی endpoint رسمی ADB فعال دارد، در پنجره RustDesk یک نگاشت از پورت محلی 15555 به میزبان/پورت دقیق endpoint گوشی بسازید.
3. درخواست Network tunnel را روی گوشی بررسی و همان مقصد را تأیید کنید.
4. پس از برقرارشدن نگاشت، از ADB ویندوز به 127.0.0.1:15555 وصل شوید.

RustDesk تونل TCP می‌سازد اما adbd یا مجوز ADB اندروید را ایجاد نمی‌کند. بدون endpoint فعال، این مسیر نیز وصل نمی‌شود.

## حریم و امنیت

- Localist Developer Options، USB debugging یا Wireless debugging را روشن/خاموش نمی‌کند.
- هیچ ADB key یا رمز نشست در تنظیمات ذخیره نمی‌شود.
- درخواست Network tunnel را فقط وقتی تأیید کنید که همان مقصد را انتظار دارید.
- قطع نشست RustDesk مسیر تونل را می‌بندد. برای لغو اعتماد ADB از تنظیمات Android استفاده کنید.
